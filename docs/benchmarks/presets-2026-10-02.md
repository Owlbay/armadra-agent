# 三预设基准（2026-10-02）

> 注（第五波 W5-C0 追记）：本报告的 `default` 是六个工具（不含 `todo`）。之后 `default` 加了 `todo`（D20），复测对照组请用 `tools.default: ["-todo"]` 还原本报告的 `default`。
>
> 由 `scripts/bench-presets.mjs` 生成。模型：packy/kimi-k2.5、packy/MiniMax-M2.7、packy/deepseek-v4-flash；预设：default、minimal、codemode；任务：fix-bug、search-summarize、multi-file-refactor；每组 1 次。
> 请求 120 次（上限 120），预算计价 $0.294（上限 $3）；**提前停止：请求数达到上限 120**。
> 「估价」按统一价 input / cacheWrite 1、cacheRead 0.1、output 4 美元每 M 计，跨模型可比，不是真实账单；「输入」= input + cacheRead + cacheWrite（模型实际读入的 token）。保温关闭。达到全局上限而中止的运行标「中止」，不进汇总。

## 环境

- 2026-10-02，本机 macOS、Node 26；ama 为本分支构建（`pnpm build`），经 SDK `createRuntime` 跑与 `ama -p` 相同的启动序列，权限 `full-auto`，任务仓库在临时目录。
- 模型经测试中转站（一个 provider，B12 的模型级 `api`：Kimi / DeepSeek 走 Chat Completions，MiniMax 走 Anthropic Messages）；中转模型目录无价格，费用一律按统一估价，预算按保守价（缓存读也按 1 美元每 M）计。
- 每组 1 次；单次运行上限 8 个请求；全局上限 120 请求、$3。实际在第 23 组触发 120 请求上限：MiniMax · minimal · multi-file-refactor 中止，MiniMax · codemode 与 DeepSeek 三个预设的 multi-file-refactor 未跑。预算计价合计 $0.294。

## 结论

1. **成功率**：跑完的 22 组全部成功（三个预设都能完成这三类小任务），差别只在成本。
2. **最省的预设随任务变**（统一估价，单组）：
   - fix-bug：Kimi / DeepSeek 上 minimal 略省（$0.0043 / $0.0116），MiniMax 上 default 最省（$0.0098）；三者差距 ≤ 30%。
   - search-summarize：Kimi 上 default 最省（3 轮、$0.0019），MiniMax 上 minimal（$0.0052），DeepSeek 上 codemode（4 轮、$0.0083）——一次脚本里并行 grep / read 少一轮。
   - multi-file-refactor（只有 Kimi 三组齐）：minimal 最省（$0.0045），codemode 最贵（$0.0103）。
3. **codemode 在小任务上不划算**：平均每组输入 token 比 default 多约 45%（12.8k 对 8.9k）（codemode 工具描述带类型声明，每轮都在前缀里），而顶层轮数并没有明显减少（平均 5.3 对 5.0）；它把 3–14 次内层调用并进一次脚本，但这些任务本来只需 2–4 次调用。按预设平均每组估价：default $0.0076、minimal $0.0076、codemode $0.0087。
4. **建议**：缺省保持 default；只读检索类、调用次数多的大任务再考虑 codemode；minimal 适合工具描述占比大的小模型 / 小上下文场景。`docs/design/design.md` §5.6 末段的结论回写交给 B9c 文档批次。
5. 缓存在三家都起作用（「其中缓存读」列）；DeepSeek 经中转以 2048 token 为粒度报缓存读，小前缀上命中率偏低（详见 `cache-2026-10-02.md` E1 / E5）。

原始数据：`docs/benchmarks/presets-2026-10-02.json`（`node scripts/bench-presets.mjs --render <json>` 可重出本报告）。
