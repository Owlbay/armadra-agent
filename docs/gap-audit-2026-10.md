# ama 缺口与默认值审计（2026-10-02，main 217017c / npm 0.3.0）

只读审计。试用环境：仓库 `git archive` 到 `/tmp/ama-audit` 后用 `tsc` 加 `build-bundle` 构建；用临时 HOME（`/tmp/ama-home*`）运行；Node 22.19 / 24.21 / 26.10 各跑一遍。真实模型只用了 packy 的 `deepseek-v4-flash`，共 2 次 `-p` 运行（约 3 次对话请求），另有 1 次 `/v1/models`，加 1 次 models.dev 拉取。

## 0. 结论先行

1. **codemode 默认开放不能直接在 `DEFAULT_CONFIG` 里写 `codemode.mode: "on"`。** 原因是显式的 `codemode.mode` 会盖过预设（`src/tools/presets.ts:37-41`），于是 `coordinator` 和 `minimal` 预设也会被加上 codemode。实测 `coordinator` 预设加上 `codemode.mode:on` 之后，模型看到的工具是 `[codemode, read]`，脚本里 `ALL_TOOLS` 却有 `bash,edit,glob,grep,ls,read,task,todo,write`，`tools.bash` 也真的执行成功了。也就是说，coordinator「不写文件、不跑 bash」的约定被绕过了。正确做法是改「跟随预设」的映射：default→on、codemode→only、minimal/coordinator→off。
2. **Node 22/24（以及 Electron 嵌入）下 codemode 属于 execute 类。** 实测 Node 22.19 的 `-p` 直接得到 `requires approval, but no one is available`；在 TUI 里则每次调用都要审批。默认开放之前，必须先决定在非 strict 运行时下的行为。
3. **`on` 模式下工具描述重复。** codemode 描述把已经直接暴露的 6 个工具的声明又内联了一遍，另外 6 个工具各追加一行提示。实测工具加 system 从约 877 token 涨到约 2233 token（+1350）。Pi 1.0 在 `on` 模式下只列出「没有直接声明的工具」。照这个做，增量能压到约 400–500 token。
4. **两个必修的健壮性问题。** 一是主请求没有超时，也没有流空闲超时：服务端发出一块数据后就停住，`-p` 会永久挂起（实测 40 s 被强杀）。二是给了位置参数的 `-p` 仍然会等 stdin 的 EOF（实测卡住）。
5. **首次使用体验。** 没有 key 时，TUI 模型选择器的首项是 `fake · 本地 › echo`，直接回车就会用上测试供应商。`-p` 在 default 模式下工具被拒时是静默的：输出 `done`，exit 0，文件没写，也没有任何提示。

### 2.3 codemode 默认开放的连带影响

- **语义（P0）**：不要把 `codemode.mode:"on"` 写进 `DEFAULT_CONFIG`。改 `effectiveCodemodeMode` 的回退分支（`presets.ts:40`）：`default→on`、`codemode→only`、`minimal/coordinator→off`。显式配置仍然优先；项目级仍然只能写 `off`（merge.ts:165-175，不需要改）。`PROFILE_DEFAULTS` 要不要给宿主默认 `off`，由 Armadra 决定（见下方 Electron 一条）。
- **权限类（P0，需要产品决定）**：`codemode` 的 `permission` 按 `capability.strict` 取 `read` 或 `execute`（`src/codemode/tool.ts:248`）。实测在 Node 22.19 的 `-p` 下被拒绝，Node 26.10 下成功。三个方案：
  - A（推荐）：只在 strict（Node ≥ 25）时默认 `on`；非 strict 时默认 `off`，只提示一次（启动时或在 doctor 里），用户显式写 `on` 才开启。语义诚实，不会每步都弹审批。
  - B：在任何运行时都默认 `on`，非 strict 时仍然每次审批。体验差，`-p` 下等于没开。
  - C：非 strict 时也按 `read` 处理（理由是内层调用都会经过权限管线）。等于放弃网络隔离这一层，与现有文档和 README 的安全说明冲突。
  - Electron 嵌入（Armadra 桌面）的 Node 主版本取决于所用 Electron；如果是 22/24，就属于非 strict，方案 A 下宿主会自然拿到 off。
- **token（P1）**：`on` 模式的 codemode 描述长 4657 字符，里面内联了 bash/edit/glob/grep/ls/read/task 等声明；另外 6 个直接工具各追加一行提示。实测工具加 system：off 约 877 token，on 约 2233 token。建议照 Pi 的做法：`on` 模式只内联「没有直接暴露的工具」（ls、task、todo、宿主工具）以及 `BashResult` 接口，直接工具只列名字、写明「参数同直接工具」。预计增量能降到约 400–500 token。基准（`docs/benchmarks/presets-2026-10-02.md`）显示 codemode 在小任务上输入多约 45%、轮数不减，默认开放之前更应该先做这一项。修改后描述字节变化，现有会话 resume 时会有一次缓存未命中，属于预期，写进 CHANGELOG。
- **预设命名（P1）**：开放后 `default` 等于 6 个工具加 codemode，而 `codemode` 预设实际是 only。建议把 `only-codemode`（或 `codemode-only`）作为正式名，`codemode` 保留为别名（0.3.0 已发布，不能直接移除）。同步更新 `TOOLS_PRESETS_STRICT_FIRST`、`--help`、README 的预设表与「什么时候用 codemode」一段（它现在写的是「缺省保持 default」）。
- **展示（P1）**：`ama config show` 不显示 `codemode.*` 和 `cache.*`，只在最后一行写「codemode off」，也不支持 `--codemode` 等覆盖参数。实测 `ama --codemode on config show` 会把 `config show` 当成提示词发给模型。需要补上这些段落和来源（「跟随预设」或「user」）。

### 2.4 `--help`、`config show`、`config.schema.json` 是否一致

- schema 里 46 个键只有 `defaultModel`、`permission.autoModel` 两个有 description，**全部没有 default** → 编辑器悬停没有信息。P1：生成 schema 时从同一张表写入 description 和 default（json-schema.ts）。
- `config show` 缺 `codemode`、`cache`、`defaultModel` 段（DEFAULT_CONFIG 里没有这几段，所以不会列出）。
- `--help` 缺：环境变量一节（AMA_LOG、AMA_SHELL、AMA_CONFIG_DIR、AMA_DATA_DIR、AMA_CACHE_*、AMA_APPROVAL_TIMEOUT_MS、NODE_USE_ENV_PROXY）；`models discover` 的 `--concurrency/--probe-timeout`；`sessions prune` 的参数。
- `/permission` 的命令说明还停留在旧值 `plan | default | auto-edit | full-auto`，缺 `auto`、`allowlist`（`src/modes/commands-core.ts:61-65`）。
- `src/ai/fake/fake-provider.ts:11` 注释说可以用 `--provider fake`，实际会报「需要同时给出 --model」。
