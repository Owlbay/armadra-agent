## 0. 结论

1. **规模**：用户可见的中文硬编码约 **1,600 行、分布在 140 个源文件**；其中约一半（≈750 处）是插值模板。重灾区：`src/modes/interactive/**`（≈420 行，33 文件）、`src/cli/subcommands/**`（≈316 行）、`src/cli/*`（help-text 84 + args/bootstrap/startup 等 ≈120）、`src/config/key-docs.ts`（113 行）、`src/modes/session-report.ts`（83）、`src/modes/commands-core.ts`（43）、`src/permissions/preview.ts`（40）。
2. **测试影响面大**：67/69 份 TUI 帧黄金（`test/fixtures/tui/*.txt`）含中文；**约 720 行断言、124 个测试文件**直接断言中文文案；RPC 黄金 `test/fixtures/rpc/external.out.jsonl` 含中文（见第 3 条）。
3. **发现「中文漏进模型上下文」的灰区**（应先改成固定英文，与语言切换解耦）：子 Agent/外部 Agent 报告 `src/drivers/runner.ts:102-104`（`工具调用：`/`修改的文件：`，已进 RPC 黄金）、工具输出截断标记 `src/agent/tool-runner.ts:213-231` 与 `src/tools/truncate.ts:189`、压缩裁剪占位 `src/compaction/prune-tier.ts:176-177`、压缩序列化 `src/compaction/serialize.ts:16`、读图错误 `src/tools/image-file.ts:211-253`、driver 失败文本 `src/drivers/native/claude-stream.ts:121-270` 等。系统提示与工具描述本身已是纯英文（`system-prompt.ts`、`plan/prompts.ts`、`agents/builtin.ts`、`skills/builtin.ts` 非注释行 0 处中文）。
4. **有 3 处逻辑依赖中文字面量**，翻译前必须改成枚举/码：`agent-panels.ts:99`（`=== "未安装"`/`startsWith("已安装")`）、`rewind-text.ts:77`（`startsWith("失败")`）、`tui/components/editor-paste.ts:61`（`includes("[粘贴 #")`）。另有**输入别名**（`plan/controller.ts:97` `批准`、`plan/extract.ts:74` 步骤标题正则）要保留双语同时识别，不随界面语言变。
5. **机制选型**：零依赖、**类型化嵌套对象目录 + 函数式插值**：`src/i18n/` 提供 `resolveLocale/setLocale/msg()`，各领域一个 `src/i18n/messages/<domain>.ts`（同文件导出 `en` 与 `zh`），**以 en 为形状源，`zh` 用 `satisfies Messages<typeof en>`，缺键/多键/参数不符在 `tsc` 期报错**；插值用箭头函数 `(n: number, path: string) => …`；复数只英文需要，用 `Intl.PluralRules("en")` 的小 helper。不引入 ICU MessageFormat 解析器。
6. **语言选择**：`AMA_LANG` > `--lang`（可选）> `ui.language`（`auto|zh|en`，缺省 `auto`）> `LC_ALL` > `LC_MESSAGES` > `LANG`；`zh*` → zh，其余（含 `C`/`POSIX`/空）→ en。**进程启动时一次定死**，不支持运行中切换。风险：macOS 中文用户常见 `LANG=en_US.UTF-8`，升级后会突然变英文——需在 CHANGELOG 与首屏提示里说明 `ama config set ui.language zh`（待定项 D1）。
7. **测试策略**：vitest `setupFiles` **把测试语言钉在 zh**——迁移批次的验收标准是「现有 67 份 zh 黄金与 720 行断言字节不变」，这本身就是迁移正确性的最强证据；另加 **en 黄金子集**（约 15 份：启动头、审批框、Plan 对话框、rewind、help，80/40 列各一）与「每个键两语都有」（tsc 保证）+「模型侧字节与语言无关」测试（同一会话 `AMA_LANG=zh/en` 两次请求前缀逐字节相等）。
8. **体积**：现在 bundle 1.36 MB，中文以 `\uXXXX` 转义存在（esbuild 缺省 `charset: ascii`，`scripts/build-bundle.mjs` 未设），≈ 9.4k 汉字 + 1.7k 全角标点 ≈ **67 KB（≈5%）**；加英文目录约 **+40~60 KB（+3~4%）**。若顺手设 `charset: "utf8"`，中文从 6 字节/字降到 3 字节/字，可抵消约一半增量。
9. **文档**：`README.md` 改英文（npm 包页只渲染 `README.md`）+ `README.zh-CN.md`；`docs/` 中文保持原路径（代码注释大量引用 `docs/xxx.md §N`），英文只译随包发布的用户文档里的核心 6 篇放 `docs/en/`；设计/计划/调研/审计类文档只保留中文；CHANGELOG 单文件（语言待定 D3）。`package.json` 的 `description` 改英文。
10. **拆分**：B0 前置（基础设施 + 键规范 + 检查脚本 + 灰区与字面量逻辑修正）串行先合；之后 B1 `cli/**`、B2 `tui/** + interactive（除第六波文件）+ permissions`、B3 其余模式与各领域、B4 配置说明与文档并行；B5 收尾第六波文件。第六波从 B0 合入起**新文案一律直接写进目录**，并且 B2 避开 `agent-panels.ts / agent-ui.ts / subagent-view.ts / commands.ts` 等第六波热点。

## 2. 机制选型

### 2.1 参照

- **工具 C**（`本机材料`，本地验证）：dist 中无任何 i18n/locale 机制（`translations` 命中只是 OpenAI SDK 的 `/audio/translations`），界面纯英文。
- **工具 B / 工具 A**（据公开资料与使用经验，本机未逐条验证）：界面文案只有英文；工具 A 的 `language` 设置影响的是**模型回复语言**而非界面。两者都没有可借鉴的界面 i18n 实现。
- 因此 ama 走自研最小方案；零依赖约束也排除了 `i18next`/`@formatjs`。

### 2.2 目录结构（推荐：按领域分文件、两语同文件）

```
src/i18n/
  index.ts          # Locale 类型、resolveLocale(env, config)、setLocale/getLocale、msg()
  format.ts         # plural、formatDuration、formatBytes/Count 的本地化版本
  catalog.ts        # 汇总各领域：{ en: {cli, tui, …}, zh: {…} }（B0 一次性建好全部领域的空壳）
  messages/
    cli.ts  subcommands.ts  interactive.ts  rewind.ts  approval.ts  plan.ts
    permissions.ts  report.ts  print.ts  config.ts  drivers.ts  session.ts  errors.ts …
```

每个领域文件：

```ts
export const en = {
  limitTurns: (limit: number) =>
    `ama: reached the turn limit ${limit} (--max-turns / limits.maxTurns); run ended early`,
  dirSummary: (files: number, size: string) => `directory, ${plural(files, "file")}, ${size}`,
  help: { list: "List commands", new: "New session" },
} as const;
export const zh = {
  limitTurns: (limit) =>
    `ama: 已达到回合上限 ${limit}（--max-turns / limits.maxTurns），运行在完成前结束`,
  dirSummary: (files, size) => `目录，${files} 个文件，${size}`,
  help: { list: "列出命令", new: "新建会话" },
} satisfies Messages<typeof en>;
```

- `Messages<T>` 是递归映射类型：字符串叶子 → `string`，函数叶子 → 同参数签名返回 `string`。**缺键、多键、参数个数/类型不符都在 `tsc --noEmit` 期报错**——这就是「覆盖率检查」，不需要运行期脚本。
- 取用：`const m = msg().print; io.stderr(m.limitTurns(event.limit))`。**嵌套属性访问优于 `t("print.limitTurns")` 字符串键**：编译期检查、可跳转、重命名安全、无运行期查表。
- 理由：集中 `zh.ts/en.ts` 两个大文件会超过 600 行上限并成为所有批次的合并冲突热点；每模块旁 `*.messages.ts` 则散落 140 处、难做覆盖与审校。按领域 10~15 个文件、每个 ≤ 600 行（`interactive` 预计要拆 `approval/plan/rewind/panels` 几份）是折中。
- **键名规范**：领域文件名即一级命名空间；叶子 camelCase、按「组件.用途」分组（`approval.title`、`approval.keys.allow`、`rewind.skip.failed`）；不以文案内容命名；整句一个键，**禁止片段拼接**（语序差异），条件分支写进函数体内。

### 2.3 运行期与懒求值

- 语言**在 `cli/main.ts` 解析参数与配置后、任何渲染前** `setLocale()` 一次；SDK（`createRuntime`）与宿主 profile 增加 `language` 选项（嵌入 Armadra 时跟随画布界面语言）。
- **模块级常量必须改成函数/getter**，否则 import 时就按缺省语言求值：`cli/help-text.ts:5 HELP_TEXT`、`permissions/modes.ts:15 PERMISSION_MODE_INFO`、`commands-core.ts:68` 起的命令表、`key-docs.ts CONFIG_KEY_DOCS`、`exit-codes.ts` 的说明表等。B0 的检查脚本可抓「顶层 `const` 引用 `msg()`」。
- 不做运行中切换（`/lang`）：消息区已渲染的历史不会回译，复杂度不值。

### 2.4 复数、数字、日期、时长

- 复数：只英文需要。`plural(n, "file")` → `Intl.PluralRules("en")` 选 `one/other`，不规则词传第三参数；Node 官方构建是 full-icu，`en` 规则在 small-icu 下也有，保底手写 `n === 1`。
- 数字：现有 `formatTokens`（`12.3k`）、`formatUsd`、`formatPercent` 是语言无关的紧凑记法，**保持不变**（状态行属 C 类）；千分位不引入。
- 时长：现有 4 个 `formatDuration` 互不一致（`status-bar.ts:81`、`session-report.ts:45`、`tool-summary.ts:86`、`print-mode.ts:111` 的 `秒/毫秒`）。建议统一到 `i18n/format.ts`：紧凑形式 `45s / 2m 10s / 1h24m` 两语共用，只有长句里的「7 分钟」走目录。
- 日期：`session/export.ts`、`sessions` 列表的时间戳保持 ISO/固定格式，不用 `toLocaleString`（黄金与机器无关）。

### 2.5 列宽

- `tui/ansi.ts:193 visibleWidth` / `:253 truncateToWidth` 已按东亚宽字符计列，库层无需改动。
- 英文字符数通常是中文的 1.5~2.5 倍，但中文每字占 2 列，**列宽大致相当或英文略长**；风险点在 40 列布局（审批框按键行、Plan 对话框选项、rewind 面板）与固定列对齐的 `--help`。`HELP_TEXT` 建议改为数据表（`[flag, desc]` 列表）按 `visibleWidth` 自动对齐，en/zh 共用排版代码。
- en 黄金必须覆盖 40 列的这些面。

### 2.6 语言选择规则

优先级：`AMA_LANG` > `--lang <zh|en>`（可选，便于脚本）> `ui.language`（`auto | zh | en`，用户级/项目级/profile 均可）> 自动检测。
自动检测：依次取 `LC_ALL`、`LC_MESSAGES`、`LANG` 第一个非空值；`/^zh/i` → zh；其余（含 `C`、`POSIX`、空、`en_*`）→ en。与 `tui/glyphs.ts:160` 的 ASCII 检测读同样的变量，但顺序按 POSIX 消息类别（`LC_MESSAGES` 而非 `LC_CTYPE`）。不读 macOS `AppleLanguages`（要起子进程，拖慢启动）。
`ama doctor` 增一行显示「界面语言：zh（来源 LANG=zh_CN.UTF-8）」。

### 2.7 模型侧隔离（硬约束）

- i18n 只能被界面层 import：B0 加守卫测试，`src/agent/system-prompt.ts`、`prompt-rules.ts`、`reminders.ts`、`tools/**`、`plan/prompts.ts`、`agents/builtin.ts`、`skills/**`、`compaction/**`、`codemode/declarations.ts` 不得 import `src/i18n`。
- 加「语言无关」测试：复用 `cli/cache-stability.test.ts` 的 harness，`AMA_LANG=zh` 与 `en` 各跑一遍同一脚本，断言发给 fake provider 的请求体（system + tools + messages）逐字节相等。
- `ui.language` **不**往系统提示里注入「请用中文回复」——那会动缓存前缀；若要控制回复语言，另立 `agent.responseLanguage` 走追加规则末尾（与 `--system-prompt` append 同位置），不在本次范围。

### 2.8 测试策略

- `vitest.config.ts` 加 `setupFiles`：`setLocale("zh")`。**迁移期间 zh 黄金与 722 行断言零改动**是每个迁移批次的验收标准——任何字节差异都说明翻译键抽取出错。
- en：新增约 15 份 `*.en.txt` 黄金（启动头 normal/header、审批框含 preview 与 origin、Plan 对话框、rewind 面板与列表、任务面板、模式选择器、`--help` 输出；各 80 列，审批/Plan/rewind 再加 40 列），加若干子命令 `--lang en` 的抽样断言。
- 覆盖：由 tsc 保证两语键集与签名一致；`scripts/check-i18n.mjs`（零依赖 node 脚本，进 `pnpm ci`）做两件事：①扫描 `src/**` 非测试、非注释、非 `src/i18n/` 的 CJK 字面量，与基线文件 `scripts/i18n-baseline.json`（每文件计数）比较，**只许降不许升**（棘轮），全部迁完后基线清零、改为「出现即失败」；白名单放输入别名（`plan/controller.ts`、`plan/extract.ts`）；②检查 en 目录里没有 CJK、zh 目录里没有遗留占位（如 `TODO`）。

### 2.9 体积

当前 `dist/bundle/ama.cjs` 1,396,130 字节；其中汉字转义 9,447 个（≈57 KB）+ 全角标点等 1,662 个（≈10 KB）。英文目录预估 40~60 KB 纯 ASCII，**总增 3~4%**。可选：`build-bundle.mjs` 加 `charset: "utf8"`，zh 部分降到约 33 KB，净增量接近 0；需确认 bundle 被 `require` 时的编码无问题（Node 按 UTF-8 读源码，安全）。不需要按语言分包或懒加载。

## 5. 风险与待定项

### 风险

- **R1 缺省语言翻转**：现有中文用户在 `LANG=en_US.UTF-8`（macOS 常见）下升级后变英文。缓解：CHANGELOG 破坏性变更里写明；首次以 en 启动且配置目录已存在旧版本痕迹时，在启动画面显示一次 `ui.language` 提示（或见 D1 改缺省规则）。
- **R2 模块级常量提前求值**：漏改一个顶层常量就会在 SDK/嵌入场景显示错语言；靠检查脚本与 en 黄金兜底。
- **R3 片段拼接**：`preview.ts`、`image-file.ts`、`rewind-text.ts` 有大量「词 + 词」拼句，直译会出现语序错误；迁移时改整句函数，工作量比行数显示的大（估计 preview/rewind 各需重构 30%）。
- **R4 测试只钉 zh**：en 布局问题只靠约 15 份黄金和抽样发现，40 列下英文截断可能漏网；B2 验收要求人工过一遍 40 列 en。
- **R5 维护成本**：此后每个界面 PR 都要写两语；`tsc` 强制齐全，但英文质量无人把关——建议 PR 模板加一项「en 文案自查」。
- **R6 灰区改动影响模型行为**：截断/裁剪标记从中文变英文，对模型理解是改善，但会让旧会话与新会话的工具结果风格不一；不影响缓存前缀。
- **R7 600 行上限**：`interactive` 领域目录两语同文件会超限，需按 approval/plan/rewind/panels 拆分；或改「同领域 `en.ts` / `zh.ts` 分两文件」——拆法在 B0 定死。
- **R8 宿主文本依赖**：若 Armadra 或用户脚本在解析 `-p` stderr / RPC `error` 文本，会被打破；在 `docs/reference/rpc.md` 声明契约只有 `code`。
- **R9 导出产物语言**：`ama sessions export` 的 Markdown 随界面语言变化，同一会话两次导出可能不同——可接受，但需在文档说明。

### 待定（需用户拍板）

- **D1** 无法判断语言时的缺省：en（国际惯例，推荐）还是 zh（照顾现有用户）？或「已有配置目录的老用户缺省 zh、全新安装按 LANG」。
- **D2** 是否提供 `--lang` 命令行参数（推荐提供，便于脚本和录制黄金），以及嵌入 Armadra 时 profile 是否下发 `language`（推荐下发，跟随画布界面语言）。
- **D3** CHANGELOG 语言：①继续中文；②从 0.6.0 起英文；③每版英文正文 + 一段中文摘要。推荐 ③。
- **D4** `config.schema.json` 描述：固定英文（推荐；静态产物、`init` 不会因切语言反复重写）还是按 locale 写。
- **D5** 是否同时引入「模型回复语言」配置（`agent.responseLanguage`，追加规则末尾、不动前缀）——与界面 i18n 解耦，建议另立项。
- **D6** 输入别名（`批准`、`步骤` 等）是否扩展英文同义词表并文档化。
- **D7** 是否顺手统一 4 个 `formatDuration` 与 bundle `charset: "utf8"`（推荐都在 B0 做）。
